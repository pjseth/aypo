# PLAN — v2, URC essentials

Three features (supplier price check, spend cleansing, market bulletin) plus the material
foundation they need, added to the existing Grain Desk without touching the wheat desk.

Written before any code. Decisions I made on my own are marked **[decision]**.

---

## 1 · What the repository actually is

Read first, not assumed:

- `app/index.html` loads **classic scripts** in a fixed order. No bundler, no modules, no
  `fetch()` — the app must run from `file://` as well as from Vercel, so the dataset is baked
  into `app/js/data.js` as `window.DESK`.
- `app/js/core.js` is one global `GD`: DOM builder (`el`), icon set, `fmt.*`, four chart
  primitives, overlays (`sheet`), router (`route`/`go`), sortable `table`, and the small
  pieces (`card` `stat` `chip` `kv` `compo` `legend` `seg` `toast` `tipOn`).
- `app/js/app.js` is the shell: rail, sidebar (groups routes by `def.group`), topbar, market
  strip built from `DESK.instruments`, command palette, Night Watch.
- `app/js/surfaces/*.js` — seven screens, each registering itself with `GD.route(key, def)`
  and capturing `var D = window.DESK` **at load time**.
- `tools/build_data.py` generates `data.js`. `tools/jscheck.py` and `tools/test_app.py` drive
  headless Edge over a throwaway localhost server (no Node on this machine).
- `app/SURFACE_CONTRACT.md` is the API a surface codes against. New surfaces obey it.

The rule that falls out of this: **surfaces capture their data at load time**, so anything
that can change at runtime (the active workspace) has to be read inside `render()`.

## 2 · Keeping the wheat workflow intact

The wheat desk is a live customer's product. The guarantees:

1. `app/js/data.js` and `window.DESK` are **not modified**. No field added, none renamed.
2. The seven existing surface files are **not modified**. Not one line.
3. `core.js` gains only additive helpers; no existing signature changes.
4. `app.js` changes in exactly three places: the sidebar head becomes a workspace switcher,
   the sidebar filters routes by workspace, and the market strip reads the active workspace's
   instruments instead of `DESK.instruments` directly. The UFM workspace's instruments **are**
   `DESK.instruments`, so UFM renders identically.
5. The default workspace is **UFM**. A fresh load of the app is the wheat desk, as today.
6. `tools/test_app.py` keeps asserting every existing route renders clean, and gains the new
   ones in both workspaces.

**[decision]** The three new surfaces appear in *both* workspaces rather than URC-only. They
are workspace-driven, the price check genuinely works on wheat, and hiding them would mean a
second rule to maintain. UFM gains three sidebar entries; it loses nothing.

## 3 · Data model

### New global `window.WS` — generated by `tools/build_ws.py`

```
as_of                 "2026-10-13"            // same clock as DESK.built
fx                    { "USD": {"PHP": 58.20, "THB": 33.02, "USD": 1}, "EUR": {...}, ... }
workspaces[]
  key                 "ufm" | "urc"
  name                "United Flour Mill" | "Demo: PH Food Manufacturer"
  short, country
  home_currency       "USD" | "PHP"
  demo                false | true             // drives the "Demo data" label
  instruments         // URC only; UFM reads DESK.instruments
  materials[]
    id, name, category "raw" | "packaging", unit "MT"|"kg", currency,
    budget_price,                              // per unit, material currency; null = none set
    budget_note,                               // where the budget came from
    drivers[]
      key, name, source, unit, currency,
      per_unit,                                // driver units consumed per 1 material unit
      offset,                                  // additive, driver currency per material unit
      kind "index" | "freight" | "spread",
      mocked true|false,
      dates[13], values[13]                    // month-end series, oldest first
    crop,                                      // weather/crop outlook feed, or null (a gap)
  suppliers[]         id, name, aliases[], materials[], country
  quotes[]            id, material_id, supplier_id, date, price, currency, unit, qty,
                      valid_to, source ("email" | "portal"), source_ref
```

### Driver cost — the one piece of arithmetic everything else rests on

For a quote on material `m` at date `d`:

```
leg_i        = (series_i(d) * per_unit_i + offset_i) * fx(currency_i -> m.currency)
driver_cost  = sum(leg_i)
premium      = quote.price - driver_cost
```

The legs are in the material's currency per material unit, so **driver legs + premium sum
exactly to the quote price** — the acceptance criterion holds by construction, not by rounding
luck. FX is not a fourth addend; it is a named, sourced multiplier shown on every leg that
needs one, plus a conversion summary row (`$4,295/MT × 58.20 = ₱250,069/MT`).

**[decision]** Every URC material is priced in **PHP**, the home currency, with USD/EUR/MYR
indices converted in. That is what the brief's own examples describe ("converted at USD/PHP")
and it puts the FX conversion on screen where a buyer can argue with it.

### Fair band

```
premiums   = [ price_j - driver_cost(m, date_j)  for every quote j on m in the last 12 months ]
band_low   = driver_cost(m, d) + percentile(premiums, 25)
band_high  = driver_cost(m, d) + percentile(premiums, 75)
```

Linear-interpolated percentile. Position is `below` / `inside` / `above`. With fewer than four
historical premiums the band is reported as **not established** rather than drawn from noise.

### Wheat as a material

`build_ws.py` emits, for the UFM workspace, one material per wheat class that actually has
quotes — drivers are the class's futures instrument (¢/bu × 36.7437 ÷ 100) and the origin's
mid Supramax freight, i.e. exactly the arithmetic `quotes.js` already performs. `DESK.quotes`
are mapped into the generic quote shape by id, so the price check can open a wheat quote and
the Quote Board is untouched.

**[decision]** UFM materials carry `budget_price: null`. UFM has no budget price anywhere in
the evidence and inventing one would be fabrication. The price check handles a null budget
with "no budget set for this material" — which is also the general case for a new customer.

## 6 · The three features

### 6.1 Supplier price check — `#pricecheck`

Page: material filter + stats + a quote table across every material, with a band column.
Clicking a row opens the sheet:

1. **Breakdown** — `GD.compo` bar: one segment per driver leg plus the premium. Legend carries
   each figure. A `kv` beneath shows every leg's arithmetic, its source and whether it is
   mocked, and a sum row proving the components equal the quote.
2. **Fair band** — a horizontal scale (plain divs, like `position.js`'s threshold bar) with
   p25/p75 marked, the quote plotted, and a word (`below` / `inside` / `above`), never colour
   alone.
3. **Budget** — amount and percent against `material.budget_price`, or an honest blank.
4. **Premium history** — `GD.chart.line`, two series: this supplier's premium by month and the
   material's median premium by month.
5. **Negotiation brief** — a button. Builds a grounded fact pack, calls `GD.llm.complete` if a
   key is present, falls back to the deterministic template otherwise, and **verifies every
   number in the output against the fact pack**; any unverified figure rejects the model draft
   back to the template with a visible note. Editable textarea, copy, download `.md`, print.

Tone: collaborative throughout. The template's talking points are "meet us at", "help us
understand", "we would like to hold the relationship" — never an accusation.

### 6.2 Spend cleansing — `#spend`

Upload (`<input type=file>`, drag-drop) or **one click** to load the baked messy sample.

- `parseCsv` — delimiter sniffing, quoted fields, BOM.
- `parseXlsx` — minimal zip reader over `DecompressionStream('deflate-raw')` + sharedStrings;
  if the browser lacks it, say so and point at the CSV. **[decision]** worth the ~90 lines
  because URC's export is an Excel file, and "no manual steps" is the claim.
- Pipeline: normalise vendor → match supplier (alias table, then token-set similarity) →
  classify material + category (learned mappings, then token scoring against name/synonyms) →
  convert to PHP → flag duplicates (same vendor+material+date+qty+amount).
- Confidence below threshold → review queue. Confirm/correct in one click. Corrections persist
  to `localStorage` under `gd.spend.map.<ws>` and are applied first on the next upload.
- Report: totals by category, material, supplier, month; price paid per unit vs budget.
- Counter line: `N processed · N auto-classified · N need review · N duplicates`.

Reconciliation: `sum(lines.amount_php where !duplicate && classified) == sum(report rows)` for
each of the four groupings. Asserted in the test suite, and shown on screen as a tick.

### 6.3 Market bulletin — `#bulletin`

Generate → one section per material: driver moves since the last bulletin (14 days), FX,
freight, crop/weather outlook, and a plain-language "what this means for buying" line. Every
figure names its source; mocked feeds are labelled. A material with a missing feed gets an
explicit "No data for this period" line rather than a filled gap — one is planted in the seed.

Draft → edit → **approve** → export. Export (PDF via a print iframe, and `.md` download) is
disabled until approved. **[decision]** no scheduled job: the app has no scheduler and adding
one for a static page would be theatre. The header states the fortnightly cadence and the next
due date instead.

## 7 · AI rules

`GD.llm` reads the key from `window.GD_ENV.ANTHROPIC_API_KEY` (written by `tools/make_env.py`
from the environment, gitignored) or `localStorage['gd.anthropic_key']`. Model `claude-opus-5`,
direct browser call with `anthropic-dangerous-direct-browser-access`. **[decision]** demo-only;
a production build puts this behind a server, and the UI says so.

Without a key — the default — every feature runs the deterministic template. In both paths the
model only ever sees the fact pack, and `verifyNumbers()` rejects any figure not in it.

## 9 · Open questions — resolved rather than asked

None were significant enough to block. The three that mattered and how I settled them:

- *Is the URC workspace a second tenant or a mode?* A second workspace, switchable, UFM
  default. It is the only shape that leaves the wheat customer's app alone.
- *What currency do URC materials live in?* PHP, with FX shown as a sourced conversion step.
- *Excel or CSV?* Both, with CSV as the guaranteed path and the sample shipped in both.
